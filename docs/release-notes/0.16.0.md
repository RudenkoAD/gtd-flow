# 0.16.0 — MCP-мост внешней синхронизации (P1)

Автоматизация теперь может оркестрировать внешнюю синхронизацию через два
новых инструмента MCP-сервера:

- **`sync_external_calendars`** — запускает полный проход внешней
  синхронизации в живом Obsidian (через файловый мост в device-local
  каталоге плагина) и ждёт **терминального** отчёта: `ok | partial | error`
  с числом обновлённых зеркал и санитизированными статусами подписок.
  Диспатч не выдаётся за успех; отсутствие запущенного Obsidian и таймаут —
  явные исходы. Результат содержит гейт `vault_sync`: продолжать последующую
  синхронизацию хранилища можно только при `ok`; `partial` — лишь с явным
  флагом `force_partial` (упавшие подписки и коды ошибок сохраняются в
  отчёте); `error` не продолжает никогда.
- **`external_sync_status`** — read-only чтение последнего санитизированного
  отчёта без скана хранилища.

Границы безопасности: учётные данные CalDAV и сетевой клиент остаются
исключительно внутри плагина; MCP-сервер видит только санитизированные
отчёты. Запросы моста адресуются конкретной установке Obsidian (стабильный
id устройства), просроченные игнорируются — реплицированные vault-sync
файлы не могут запустить синхронизацию на чужой машине.

Совместимость: минимальная версия Obsidian — 1.11.4 (как в 0.15.0).
MCP-контракт расширен добавлением двух инструментов; существующие девять
не изменились.
