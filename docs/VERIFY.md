# Сквозная верификация GTD Flow (ТЗ §14)

Ручной чек-лист для прогона человеком в реальном Obsidian. Автотесты (`npx vitest run`)
покрывают логику; здесь — то, что автотестами не покрыть: реальный DOM, drag, кэш
метаданных, границу Android/desktop и pop-out.

## Подготовка

1. Перед первым browser-прогоном установите закреплённый Chromium:
   `npx playwright install chromium`. Затем запустите полный локальный gate:
   `npm ci && npm run verify` (lint/format, coverage, Svelte compiler и semantic
   checks, mounted browser/axe tests, typecheck и production-сборка).
2. Создайте **новую** папку тестового vault:
   `node scripts/gen-test-vault.mjs ../gtd-flow-test-vault --files 100 --tasks 20`,
   затем откройте её в Obsidian. Генератор откажется использовать существующую папку.
   `--force` разрешён только для ранее сгенерированного vault с маркером
   `.gtd-flow-test-vault`; никогда не направляйте его в реальный vault.
3. Подложите плагин символической ссылкой, чтобы пересборка подхватывалась сама:
   - Windows (cmd от администратора не нужен для junction):
     `mklink /J "<vault>\.obsidian\plugins\gtd-flow" "D:\projects\claude_home\calendar_app"`
   - macOS/Linux: `ln -s /path/to/repo <vault>/.obsidian/plugins/gtd-flow`
   - либо просто скопируйте `main.js`, `manifest.json`, `styles.css` в
     `<vault>/.obsidian/plugins/gtd-flow/`.
4. Включите GTD Flow в «Настройки → Плагины сообщества». После правок кода:
   пересборка + `Ctrl/Cmd+P → Reload app without saving`.
5. Выполните команду **«Открыть рабочее пространство GTD»**.

Консоль разработчика (для пунктов 7–9): `Ctrl+Shift+I` (Windows/Linux) / `Cmd+Opt+I` (macOS).

## 1. Тикль (отложенный ящик)

- [ ] Во «Входящих» перетащите «Позвонить в сервис…» в «Отложенные» на будущую дату
      (или на день вперёд в календаре бакета).
      **Ожидаемо:** в `GTD/Inbox.md` у строки появился `🛫 <дата>` (и `🆔`, если его не было);
      карточка исчезла из «Входящих» и появилась в «Отложенных» в нужном бакете.
- [ ] Наступление даты: закройте Obsidian, переведите системные часы за дату `🛫`
      (или отредактируйте `🛫` на вчера), откройте снова.
      **Ожидаемо:** задача сама во «Входящих» — при этом файл **не менялся** (проверьте
      mtime/дифф: «возврат» — чистый пересчёт).
- [ ] «Закрытый период»: держите Obsidian закрытым несколько «дней» (сдвиг часов),
      откройте. **Ожидаемо:** всё, чей `🛫` уже в прошлом, во «Входящих»; ошибок в консоли нет.
- [ ] Кнопка «вернуть сейчас» в «Отложенных» — задача мгновенно во «Входящих»
      (единственная запись: снят/сдвинут `🛫`).

## 2. Регулярные

Шаблоны — в `GTD/Recurring.md` сгенерированного vault (`rev-week`, `rev-prio`, пауза `park-permit`).

- [ ] Первый запуск: после полной загрузки у шаблонов без `🔜` курсор проставился сам
      (bootstrap, без ретроспективных копий).
- [ ] Спавн: отредактируйте `🔜` шаблона `rev-week` на сегодня, выполните команду
      **«Проверить регулярные сейчас»**.
      **Ожидаемо:** в `GTD/Inbox.md` появилась копия с `🆔 rev-week-<YYYYMMDD>` и
      `🧬 rev-week`, без `🔁`/`🔜`; курсор шаблона сдвинут на следующую пятницу.
- [ ] Идемпотентность: выполните команду ещё раз. **Ожидаемо:** дублей нет, ничего не записано.
- [ ] Офсеты: у `rev-prio` (`every month on the last day 🛫 -3d`) копия несёт абсолютный
      `🛫` = дата вхождения − 3 дня.
- [ ] Догон (catchUp=latest): сдвиньте `🔜` какого-нибудь шаблона на 3 месяца назад,
      запустите проход. **Ожидаемо:** ровно **одна** свежая копия, курсор в будущем.
- [ ] Два устройства: скопируйте vault целиком, прогоните проход в обоих, слейте файлы
      (скопируйте обе копии-строки в один `Inbox.md`). **Ожидаемо:** после переиндексации
      дедуп сходится к одной строке; изменённая руками копия всегда выживает.
- [ ] Пауза: `park-permit` (статус `[-]`) не спавнится; в виде «Регулярные» помечен паузой.

## 3. Проекты (граф)

Проект — `Projects/Ремонт кухни.md` сгенерированного vault.

- [ ] Откройте файл проекта → вид «GTD: Проект». **Ожидаемо:** граф: «Обмерить кухню»
      (done, зелёный), «Собрать сметы»/«Выбрать технику» готовы/в работе, «Заказать
      материалы» заблокирован (замок), «Запланировать монтаж» — тикль (часы).
- [ ] Ребро: протяните ребро от «Собрать сметы» к «Запланировать монтаж».
      **Ожидаемо:** в строке цели появился id в `⛔` (через запятую к существующим).
- [ ] Цикл: попытайтесь протянуть ребро, замыкающее цикл (например, от «Заказать
      материалы» обратно к «Собрать сметы»). **Ожидаемо:** отказ с подсветкой уже при
      протяжке; в файл ничего не записано.
- [ ] Всплытие: выполните «Собрать сметы» и «Выбрать технику». **Ожидаемо:** «Заказать
      материалы» сам появился во «Входящих» — файл проекта при этом не менялся.
- [ ] Un-done: снимите галочку с «Собрать сметы». **Ожидаемо:** «Заказать материалы»
      исчез из «Входящих» обратно (тоже без записи).
- [ ] Авто-layout: кнопка раскладки перестраивает граф; frontmatter `layout` обновился
      одной записью.

## 4. Kanban / Календарь

Доска — `Boards/Работа.md` сгенерированного vault.

- [ ] Drag карточки между колонками «К работе» → «В работе» → «Готово».
      **Ожидаемо:** в строке меняется только тег колонки
      (`#kanban/work/todo` → `#kanban/work/doing` → `#kanban/work/done`), порядок в
      frontmatter `order` обновляется, а checkbox-статус и дата завершения не меняются.
- [ ] Drag внутри колонки — меняется только порядок (frontmatter), строки задач нетронуты.
- [ ] Календарь: перетащите «Продлить страховку» (📅 2026-07-20) на другой день.
      **Ожидаемо:** `📅` в `GTD/Inbox.md` сменился; во «Входящих»/доске карточка согласована.
- [ ] Клик по пустому дню календаря — быстрый ввод новой задачи с датой этого дня.

### Полный редактор задачи (Inbox / Kanban / Tickler)

- [ ] В каждом из трёх видов кликните по свободной области или бейджу карточки вне
      названия. **Ожидаемо:** открылся диалог «Задача» с актуальными названием,
      выполнением, приоритетом, тремя датами и временем, местом, длительностью,
      интенсивностями и scope; системные сведения показаны отдельно.
- [ ] Измените несколько обычных и estimate-полей одновременно и нажмите
      **«Сохранить»**. **Ожидаемо:** диалог закрылся, все изменения появились в одной
      целевой Markdown-строке без частично применённого набора; соседние строки не
      изменились. У id-less задачи перед сохранением может отдельно появиться `🆔`.
      Ручные `⏱`/`🧠`/`💓`/`💪`/`🧭` стали user-owned/locked и не перезаписываются
      следующим AI-запуском, а нетронутые AI-поля не заблокировались.
- [ ] Проверьте ошибки по очереди: пустое название, `13`/`2220` минут, несуществующая
      дата, интервал с концом не позже начала и одновременные `📅` + `🛫`.
      **Ожидаемо:** видна ошибка, **«Сохранить»** недоступно, диалог остаётся открыт,
      Markdown не меняется. После исправления форма снова сохраняется.
- [ ] Нажмите **«Отмена»** или `Escape`. **Ожидаемо:** диалог закрылся без записи.
      Двойной клик по названию по-прежнему включает inline-редактор: `Enter`
      сохраняет переименование, `Escape`/потеря фокуса отменяет; одиночный клик по
      названию не открывает полный редактор.
- [ ] Нажмите checkbox, меню, ссылку и индикатор чеклиста, затем перетащите карточку.
      **Ожидаемо:** каждый control выполняет своё действие без открытия диалога;
      успешный drag не открывает редактор после drop, а обычный клик без drag — открывает.

## 5. Кросс-видовой DnD

- [ ] «Входящие» → колонка доски. **Ожидаемо:** у строки появился тег колонки, задача
      ушла из «Входящих» (появился `#kanban/…` ⇒ разобрана).
- [ ] Карточка доски → день календаря. **Ожидаемо:** в строке появилась `📅`, «событие»
      видно в календаре, карточка осталась в своей колонке.
- [ ] «Входящие» → полотно открытого проекта. **Ожидаемо:** строка **переехала** из
      `Inbox.md` в файл проекта (append туда, удаление из источника), получила `🆔`
      и координаты в `layout`.
- [ ] Pop-out (десктоп): вытащите вид в отдельное окно. Внутри окна drag работает;
      **между** окнами drag не поддерживается — используйте контекстное меню карточки
      «Переместить в…» (это ожидаемое поведение, не баг).

## 6. Карточка (заметка-деталь)

- [ ] На любой задаче во «Входящих»: «Открыть карточку». **Ожидаемо:** создана заметка
      `GTD/Cards/<🆔> <название>.md` с frontmatter `gtd-card-of: <🆔>`, в строку задачи
      добавлена `[[ссылка]]`, заметка открылась в соседнем сплите.
- [ ] Добавьте в заметку-карточку чеклист `- [ ] шаг 1` / `- [ ] шаг 2`.
      **Ожидаемо:** эти пункты **не** появились во «Входящих» (состояние DETAIL);
      на карточке задачи виден прогресс `0/2` → `1/2` по мере выполнения.
- [ ] Повторный вызов «Открыть карточку» открывает существующую заметку, а не плодит новую.

## 7. Целостность файлов

- [ ] Сделайте копию vault до прогона (или `git init` в тестовом vault). После пунктов
      1–6 просмотрите диффы всех `.md`.
      **Ожидаемо:** правки ТОЛЬКО в целевых строках задач и frontmatter (`order`,
      `layout`); соседние строки, пустые строки, заголовки, порядок полей в нетронутых
      строках — байт-в-байт как были (round-trip без потерь).
- [ ] У задач, которых плагин не касался, не появилось «самопроизвольных» `🆔`
      (ленивая вставка — только при первой структурной правке; в проектах — сразу, это норма).

## 8. Universal bundle и Android boundary

- [ ] `npm run check:packaged-plugin` — после production-сборки проверяет manifest,
      обязательные артефакты, отсутствие eager Node/Electron imports, отсутствие
      конкретных credential-shaped строк и загрузку `main.js`, когда Node/Electron
      недоступны. Это smoke-gate упаковки, но не заменяет запуск в реальном Obsidian.
- [ ] На desktop проверьте pop-out: внутри отдельного окна действия и drag работают;
      между окнами используйте контекстное меню карточки.
- [ ] Убедитесь, что release `manifest.json` содержит `isDesktopOnly: false`, а
      `npm run check:packaged-plugin` сообщает `eager: none`: bundle обязан
      загружаться без Node/Electron.
- [ ] На Android установите release bundle и откройте плагин. **Ожидаемо:** доступны
      только виды «Входящие», «Календарь» и «Регулярные»; общий редактор задачи
      открывается из этих видов. AI, OAuth, проекты, доски, tickler и desktop DnD
      не регистрируются и не показываются в настройках/командах.
- [ ] Проверьте cold и warm запуск URI для vault с кириллицей и пробелами:
      `obsidian://gtd-flow?vault=<vault>&view=inbox` и
      `obsidian://gtd-flow?vault=<vault>&view=calendar&mode=day&date=YYYY-MM-DD`.
      **Ожидаемо:** открывается нужный vault и точный день; невалидная дата или view
      ничего не меняют.
- [ ] В мобильном редакторе измените duration, три intensity и scope, затем дождитесь
      синхронизации на desktop. **Ожидаемо:** Markdown обновлён атомарно, ручные поля
      помечены user-owned и следующий AI-run их не перезаписывает.
- [ ] На Android создайте, измените и поставьте на паузу recurring-шаблон, затем
      выполните «Проверить регулярные сейчас». Запустите тот же проход одновременно
      на Android и desktop. **Ожидаемо:** для одного вхождения остаётся не более одной
      задачи с детерминированным ID; после офлайн-слияния схождение начинается от
      изменения индекса. Старый шаблон без `🆔` получает одинаковый детерминированный
      родительский ID на обеих репликах.
- [ ] Простое открытие Android Obsidian не запускает onboarding, AI, external calendar
      polling или desktop promote-мутации. iOS остаётся вне матрицы этого релиза.
- [ ] На Android с настроенным CalDAV-аккаунтом убедитесь, что сам плагин не ходит
      в сеть за CalDAV: `plugin.sync` остаётся `null`, CalDAV-провайдер не
      композится (композиция происходит только за desktop-веткой в `main.ts`).
      При этом события CalDAV, уже материализованные в зеркало на desktop,
      видны в Android-календаре — их доставила ваша синхронизация хранилища
      (Obsidian Sync / Remotely Save), а не сам плагин.

### CalDAV fail-closed проверки

- [ ] Переключите коллекцию `details → busy`, затем оборвите сеть/выключите
      Obsidian до завершения зачистки. **Ожидаемо:** после перезапуска
      `pendingRedaction` остаётся `true` и зачистка (корзина зеркала + снятие
      маркера) повторяется автоматически — ни при каком отказе детальное
      зеркало не остаётся синкающимся или молча помеченным «готово».
- [ ] Испортите одну запись `externalCalendars`/`caldavAccounts` в `data.json`
      вручную (например, обрежьте JSON или сотрите обязательное поле) и
      перезапустите Obsidian. **Ожидаемо:** повреждённая запись становится
      `InvalidCalendarSub` — видна в настройках как «Повреждённая запись
      подписки», не синкается и не активируется молча; соседние подписки не
      затронуты.
- [ ] На хранилище с испорченной вручную записью внешнего календаря запустите
      MCP-инструменты (`gtd_overview`, `list_events`, `list_tasks`).
      **Ожидаемо:** инструменты отвечают нормально по остальным данным
      хранилища и не падают из-за одной битой записи календаря.

## 9. Unified inbox, scopes and AI

- [ ] В **Настройки → Входящие** задайте отдельный `GTD/Inbox.md`. Быстрый ввод,
      экземпляр регулярной задачи и возврат tickler должны писать только в этот
      единый файл, без namespace selector.
- [ ] В **Scopes** создайте `Work`; добавьте строку
      `- [ ] Invoice ⏱ 90m 🧠 4 💓 2 💪 0 🧭 work`.
      **Ожидаемо:** парсер показывает `1h 30m`, три независимые интенсивности и
      имя scope; `0` у физической интенсивности означает «неприменимо».
- [ ] Проверьте границу длительности: `⏱ 1440m` показывается как `1d`, `⏱ 2880m`
      как `2d`; начиная с `24h` принимаются только точные кратные суткам (`24h`,
      `48h`, …), а `⏱ 2220m` не принимается редактором/AI/MCP как `37h`.
- [ ] В **AI и оценки** включите AI, при необходимости включите строгий ZDR, затем
      **Подключить**. **Ожидаемо:** OAuth открывается только после клика,
      использует desktop callback; после перезапуска Obsidian соединение отсутствует
      и требует reconnect. Не ищите ключ в Markdown, `.gtd-flow` или `data.json`.
- [ ] Выполните **«Обработать входящие с AI»** на тестовой задаче. Подтвердите, что
      запуск создаётся только по команде, а при rate limit ожидающий запуск не
      выполняется сам; **«Повторить ожидающие AI-запуски»** делает явную попытку.
      HTTP 429 должен отображаться как ожидание свободной ёмкости
      (`rate_limited`), а иная временная ошибка провайдера — как ожидание повтора
      (`retry_waiting`), без сообщения об исчерпанной квоте.
- [ ] Ответьте на уточняющий вопрос AI и убедитесь, что новый запрос не отправлен.
      Затем выполните **«Переоценить задачу под курсором с AI»**.
      **Ожидаемо:** создаётся новый запуск только после команды; ответ передаётся
      лишь для связанных полей, которые всё ещё принадлежат AI.
- [ ] Измените одно AI-заполненное поле вручную, затем повторите обработку.
      **Ожидаемо:** поле остаётся защищённым до **«Разблокировать AI-поле задачи
      под курсором…»**.
- [ ] В **AI и оценки → История обучения** откройте просмотр, экспортируйте JSON и
      проверьте очистку после подтверждения. **Ожидаемо:** просмотр ограничен
      последними 50 событиями и показывает владение полями без текста задач,
      путей и данных авторизации; экспорт остаётся доступен для полной локальной
      диагностики.
- [ ] Для legacy vault: создайте backup, запустите **«Мигрировать пространства в
      scope…»**, построьте dry-run и убедитесь, что vault не изменился. Примените
      план, сохраните journal ID из `.gtd-flow/ai/migrations/`; отдельно проверьте
      **«Продолжить…»** на прерванном плане и **«Откатить…»** на завершённом плане.

## 10. Юнит-прогон

- [ ] `npx vitest run` — весь набор зелёный (property round-trip сериализатора,
      клампинг дат повторов, циклы графа, дедуп, полночь, перф-смоук 10k задач).
- [ ] `npm run test:coverage` — весь набор зелёный и обязательные пороги покрытия
      для `core`, `services` и MCP не снижены.
- [ ] `npm run check:svelte:semantic && npm run test:browser` — semantic Svelte
      check, mounted Chromium-компоненты и axe не находят ошибок.
- [ ] `npm run build` — purity-проверка ядра + typecheck + production-сборка без ошибок.
